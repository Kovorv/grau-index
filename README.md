### 筛选：一行组合框（默认）
每个维度是一个按钮，点开就是一个**带搜索的下拉**，选项后面带条目数：

- **直接换值**：再点另一个选项即可，不需要先取消原来的选择；

### 器材类型是怎么判定的
21 个类型（20 类 + `其他器材`）由 `_raw\classify.cjs` 逐条判定，主表的「器材类型」筛选按钮与详查索引的「器材类型」表都用它，**不引用任何外部分类**——完全按条目自身的说明文字打分。

- **分词打分**：每个类型有一组关键词（俄文 + 中文）。俄文短词干（`мин`、`бтр`、`сау`）只能**词首**匹配，长词干（≥5 字符，如 `взрывател`、`снаряд`）允许在**复合词内部**命中，所以 `радиовзрыватель`、`артснарядов` 不会漏；`ё/е` 混写在匹配前统一成 `е`；
- **特指度与位置权重**：命中词的权重 = `特指度 × 位置权重`，特指度按词长（越长越具体），位置权重取「描述开头说的事更重要」（俄文说明是中心词在前），每个词最多计 4 次；
- **GUARD（防误吞）**：`гранат` 后面不能是 `омет`（否则「火箭筒」被当成「弹药」）、`автомат` 后面不能是 `ическ`（否则「自动炮」被当成「轻武器」）、`заряд` 后面不能是 `н/чик`、`тара` 后面不能是 `н/риф`……共 12 组；
- **俄文原文优先**：先只用俄文原文打分；俄文没有任何命中时才用中文译文打分（中文列只是俄文的翻译，不能盖过原文）；两者都没有命中时才回退到源目录的族标题（如「средства управления, командные пункты」）；仍无命中 → `其他器材`；
- 同分时按固定类型顺序决定（`TYPE_ORDER`）。

结果：`其他器材` 403 条（3.5%），其中 251 条本来就没有说明文字（源目录只给了编号）。审计脚本：`_raw\audit_type.cjs`（分布、与族标题的分歧、逐类抽样）、`_raw\audit_type2.cjs why <索引>`（单条逐关键词得分拆解）、`_raw\audit_type3.cjs`（新旧判定差异清单）、`_raw\sample_type.cjs <类型…>`（抽样核对）、`_raw\type_of.cjs <索引…>`（查某条现在的判定）。

### 怎么用
- 索引号后面出现蓝色 **`W`** 徽标 → 点开卡片：缩略图 + 条目名（点标题新窗口打开维基）+ 首段简介 + 底部一行「匹配依据 · 来源说明」；缩略图读不到时自动收起，只留文字；
- 徽标分两级：**实心蓝**（正文比对确认）／**淡蓝**（按名称对应），悬停提示和卡片底部都会写明依据；
- 筛选栏 `维基：全部 → 维基：有条目 · 2227 → 维基：无条目 · 9392`，三态循环，状态记忆在 `grauWiki`；
- CSV 的 `wiki;wiki_url;wiki_intro;wiki_lang;wiki_tier;wiki_langs` 六列、XLSX 索引总表的同名列与之对应（`wiki_langs` 列出该行卡片里能切换的全部版本）。

### 取数方式（`_raw/wiki_batch.cjs`）
搜索接口按访客身份限流，一开始整批 429。查明后确认：维基按 User-Agent 分档——UA 里没有可联系的网址／邮箱只给 **10 次/分钟**，带上网址或邮箱给 **200 次/分钟**（`_raw/ua_test.cjs` 实测 8/12 → 12/12）。所以：

1. **不搜索，直接猜标题再批量解析**：每个索引号先试它自己（如 `9К37`），再试说明里引号中的俄文名（如 «Бук»）；
2. 用 `action=query&titles=…&prop=extracts|pageimages|info` 一次 18 个标题（匿名客户端 `exlimit` 上限 20），间隔 400 ms ≈ 150 次/分钟；
3. 共 **818 次请求**，拿到 **3 215 条**候选（`_raw/wiki/pages.json`），0 失败。

### 精度把关（关键）
按名称命中的候选里**大量是同名普通词**——`8А92 → Восток`（东）、`9М23М → Град`（冰雹）、`1РЛ14 → Енисей`（叶尼塞河）、`МРКП-58 → Буран`（暴风雪）。作为一本查阅用的对照表，**错链比缺链更糟**，所以做了两道筛：

1. `_raw/wiki_verify.cjs` 拉取候选条目的**完整 wikitext**（45 个标题一批，23 次请求）做同形字折叠 + 边界锚定的索引号检索 → 304 条命中，加上第一手标题命中，共 903 条确认为真；
2. 其余候选要求「简介含军事装备词汇（`индекс ГРАУ`／`по классификации НАТО`／ракет／комплекс／танк／ЗРК…`）**且**提到某个 ГРАУ 形状的编号（`\d{1,2}[А-ЯЁ]{1,3}\d{0,4}`）**且**不是消歧义／别类词条（`может означать`／`многозначн`／`топоним`／`род растений`…）」→ 再留 260 条。

最终 `3 215 → 1 118`，另外 2 097 条判为无关词条丢弃；没有维基条目的索引号再回落到维基教科书词表（417 条，`glossary_links.json`），合计 1 535 条（`_raw/wiki_pack.cjs` 的 `tierOf()`，`--stats` 可复核）。消歧义／总览页（`Смельчак: … — фильм, … — комплекс`）另行排除，避免把人名词条挂在编号上。

### 为什么工兵没有「ГИУ 索引」
俄文维基《Индекс ГРАУ》只覆盖 УРАВ ВМФ／УВ ВВС／УВ ПВО（5，后为 6，结构反过来）／УРВ РВСН（8、15）／ГУКОС（11、14、17），**没有 ГБТУ，也没有 ГИУ**。工兵器材在官方目录里是用 **КД 代号 + КВТ／ОКП／ЕКПС 分类码**编目的，全文 436 页**没有出现过一次带「индекс」的词**。真正带索引号的工兵器材是**旧 ГАУ 的 56／57 部门号**（地雷、炸药块、点火管、爆破器材），以及近年 РПО／ТОС 一类的 `МО.NN.NN` 号——本目录把这两类都收进来了。

### 数据来源与解析
- `_raw\gbtu_fetch.cjs` 抓 7 个源到 `_raw\gbtu\`：bmz.ru「Обозначение техники (Индекс) ГАБТУ」（494 段）、русская-сила.рф 的 ГБТУ／ПВО／ВАТ／ГРАУ 四张 `<pre>` 清单（**该站没有 ГИУ 页**，index_giu／viu／vat 均 404）、俄／乌维基百科 wikitext 表、guns.ru 索引汇编（304 KB 正文）、国防部工程器材目录 PDF（5.8 MB）。
- `_raw\gbtu_parse.cjs --write` → `_raw\gbtu\gbtu.json`：按「对象号」合并（`Объект`／`Об’єкт`／`Изделие` 前缀归一、大写、Ё→Е），**每个来源各存一份 label／代号／说明**（`srcs`），顶层字段取「说明最长的那个来源」，避免混搭；`sila=479 bmz=490 ruwiki=60 ukwiki=337 → 590 条，其中 413 条有代号、475 条多来源、42 条存在来源间代号冲突`。
- `_raw\giu_parse.cjs --write` → `giu_items.json`（208 项）＋ `gau5657.json`（478 条 56/57 号）＋ `mo_idx.json`（11 条）。条目名取自「1. Назначение и особенности конструкции」段落里 «… предназначен…» 的主语（页首行在全文只出现一次的也算条目名），并做**去连字符**处理（PDF 把「предна- значен」拆开会让条目漏掉）。
- PDF 转文本：`_raw\pdf_dump.py`（PyMuPDF，输出 `katalog_siv_1.txt`）。注意 **Python 在这个环境里 stdout 是 GBK，打印西里尔字母会 `UnicodeEncodeError`**，所以文本分析一律用 Node。
- 导出：`node _raw\build_oth_csv.cjs` 生成 4 个 CSV（UTF-8 BOM）；`build_xlsx.cjs` 会顺带把这四层写成 4 个工作表。

## 数据口径

- 条目录入 **11 590** 条；其中 11 374 条有俄文说明（182 条源站本身未写说明），缺译 0。
- 来源：russiansila（ГРАУ 分组表）、500maketov.ru（ГРАУ/ГАУ + 五个非 ГРАУ 设计局）、SALIS3 PDF（2011-06-11）；另有**网络补充层 269 行**（见上节，逐条带出处）与**卡片层**（俄文维基 1 118 条 + 维基教科书词表 417 条 + RWD 目录 244 条 + 网络配图，另含 7 933 条其他语言版本）。
- 卡片层里「编号是纯数字」的误配（维基把 `8` 解释成自然数）在装配时统一剔除（`build_v1.cjs` 的 `CARD_JUNK`）。
- v1.1 的文本清理：573 条里的存疑标记（`?`／`(?)`／`（推测？）`）已规范化——标记去掉、被标记的词本身保留；264 条介绍被重写或拆分（合并条目、图例串入说明）；这些改写都记在 `_raw\desc_fixes.json` 与 `_raw\qmark_log.json`（逐条前后对照，可回退）。
- 其余条目保留源文原貌：拼写错误、`***`／`фейк` 等标记、编号与说明不符等一律不"纠正"（补充层的 `订正` 两条是例外，已标注出处）。
- 俄文与中文尽量取自同一来源文本；无法对齐时以俄文（SALIS3）为准。
- 「器材类型」是按条目说明文字**自动判定**的（见上节「器材类型是怎么判定的」），源目录里并没有这一列，个别条目仍可能归错类；`其他器材` 里 251 条是源站根本没写说明的编号。
